# Harness Monitor

## Register
Product. Existing Harness operators need to understand progress, blockers,
verified outcomes and retained invocation usage while developing a project.

## Platform
Web; a local read-only browser UI alongside the existing portable CLI.

## Purpose
Answer: what is happening, what is blocked, what needs human attention, and what
usage is confirmed? Use actual repository records; never seed a live screen with
demo numbers. Keep unknown, unavailable, stale and zero distinct.

## Design
Continue the approved light dashboard concept: restrained blue, neutral surfaces,
system Korean-capable sans, clear task rows and one compact summary strip.
The operator reads this beside an editor in a lit workspace; prioritize readable
text and explicit states over decoration. Keyboard support, narrow-screen reflow,
text labels for every status and visible focus are required.

## Boundaries
No launch, retry, approval, merge, remote publication, billing or quota actions.
No raw prompt / provider logs in the browser. First version uses retained queues
as its denominator; it does not claim a complete un-dispatched project plan.
